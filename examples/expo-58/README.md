# Expo SDK 58 example (dev build)

An Expo SDK 58 app, created with `npx create-expo-app@latest --template blank-typescript`, that uses the afterdb
packages under their usual names: `import Realm from "realm"` and `@realm/react`. It runs the same self-check as
`../../example` (bare React Native 0.88): CRUD on a Projects/Tasks model (`schema.ts`), link, list, embedded object,
backlink, queries, an encrypted realm (64-byte key), the live hooks `useQuery` and `useObject` inside
`RealmProvider`, and a launch counter kept on disk. The screen shows `AFTERDB_SELF_CHECK_OK` when every check passes;
the result is also written to `selfcheck-result.realm`. `App.tsx` and `schema.ts` are copies of the files in
`../../example` (only the comment at the top of `App.tsx` differs): keep them in step.

It needs a dev build: realm is a native module, so it does not run in Expo Go.

Versions: Expo SDK 58.0.23, React Native 0.88.1, React 19.3.0, TypeScript 6.0.3. New architecture and Hermes (Expo
defaults). Android: Gradle 9.4.1, AGP 9.2.1, NDK 27.1.12297006, compileSdk 37, targetSdk 36, minSdk 24. Android
package and iOS bundle identifier: `com.afterdbexample.expo58`.

## Dependencies

`package.json` points `realm` and `@realm/react` at the tarballs built in this repository (`file:` paths), so the
example works without a registry. Build them first from the repository root (`npm run build`). In your own app, use
the npm aliases instead:

```json
"realm": "npm:@pomwik/afterdb@20.3.0",
"@realm/react": "npm:@pomwik/afterdb-react@0.20.1"
```

`package-lock.json` is not committed: it pins the integrity of the local `.tgz`, so npm would silently keep an old
package after a rebuild.

## R8: no ProGuard rule needed in the app

Expo SDK 58 turns R8 on for release builds (`android.enableMinifyInReleaseBuilds=true` in the generated
`gradle.properties`). The native library looks up `io.realm.react.util.SSLHelper` by name only (`FindClass` in
`JNI_OnLoad`); without a keep rule, R8 removes it and the release app crashes at start with
`ClassNotFoundException`. The package ships the rule (`binding/android/consumer-rules.pro`:
`-keep class io.realm.react.** { *; }`) and Gradle adds it to the app's R8 configuration on its own. The app needs no
`expo-build-properties` plugin and no rule in its own `proguard-rules.pro`. The same holds for a bare React Native app
that turns R8 on (`enableProguardInReleaseBuilds = true`).

## Build for Android

```bash
npm install
npx tsc --noEmit
npx expo prebuild --platform android --clean
cd android && ./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a,x86_64 && cd ..
node ../../scripts/check-16kb.mjs android/app/build/outputs/apk/release/app-release.apk
```

`android/` and `ios/` are generated by `expo prebuild` and not committed. As in the Expo template, the release APK
is signed with the debug key.

In CI, the `expo-android` job runs these steps and keeps the APK; `expo-android-run` (started by hand, with the
emulators option) runs it on an Android 16 emulator with `scripts/android-selfcheck.sh`.
